# Skill Authoring Evidence Patterns

Use this reference when closure depends on changed-skill-to-validation mapping, body-vs-reference placement proof, routing or pressure evidence, generated artifact freshness, source-vs-dist boundaries, or validation proof limits. Keep the capability body for authoring rules; load this file only when preparing concrete closure evidence.

## Claim To Evidence Map

| Claim | Minimum evidence | Does not prove |
| --- | --- | --- |
| Body remains efficient | `SKILL.md` line count, moved/deferred detail map, selected references, and anti-bloat validator result. | The skill is easy for every future prompt. |
| Reference is loadable | Link from `SKILL.md`, precise loading condition, link validator pass, and dev/recommended build when the build profile matters. | The reference will be chosen correctly without a trigger or guard. |
| Trigger change is safe | Routing case or explicit no-routing-impact rationale plus over-routing guard for trivial docs/comment work. | Universal route precision across all prompts. |
| Discipline rule changes behavior | Baseline failure or expected-behavior case, pressure scenario or rationalization list, and validator result. | Real-world agent adoption without future eval coverage. |
| Generated artifacts are fresh | Source edit, generator command, reports/dist/runtime link/install validation, and source-vs-generated boundary note. | External installation state outside the validated workspace. |
| Closure evidence is current | Final changed-path list, command order after final edit, result artifacts, proof limits, rollback note, and residual owner. | Broad completion beyond the changed skill surface. |

## Changed Skill Validation Map

```yaml
changed_skill_to_validation_map:
  skill_or_reference: ""
  changed_behavior: ""
  body_reference_decision: keep_in_body | move_to_reference | split | defer
  routing_impact: none | trigger_changed | guard_changed | registry_changed
  validation:
    commands: []
    generated_artifacts: []
    proves: []
    does_not_prove: []
  residual_risk_owner: ""
  rollback_note: ""
```

## Closure Checks

- Do not report a score movement as professional improvement unless the changed rule has a behavior, loading, routing, or evidence effect.
- Treat generated reports as stale when source edits occur after the report command.
- Name skipped pressure/routing fixtures when only structural validators ran.
- Keep personal archive ingestion, source install, private corpus mapping, and direct `dist/` edits out of skill-authoring evidence.
