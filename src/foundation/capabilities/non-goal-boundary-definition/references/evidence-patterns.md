# Non-Goal Boundary Definition Evidence Patterns

Use this reference when scope-boundary closure depends on forbidden-artifact proof, not-present validation freshness, prior source or task evidence reuse, tool permission boundaries, or proof limits. Keep it as an evidence map, not a second scope-classification guide.

## Scope-Claim-To-Validation Map

| Scope claim | Minimum evidence | What it proves | What it does not prove |
| --- | --- | --- | --- |
| Non-goal is specific and enforceable | Named excluded behavior, excluded surface, owner, current release boundary, and not-present check | The inspected scope boundary can be reviewed and tested | Future backlog priority or stakeholder alignment is settled |
| Deferred work created no placeholder artifact | Diff or source search across API, schema, UI, permissions, jobs, events, flags, docs, and tests | Obvious speculative surface was not introduced in inspected paths | Generated artifacts or undiscovered dynamic routes are absent everywhere |
| Required control was not invalidly deferred | Security, privacy, reliability, accessibility, data integrity, compliance, and compatibility review for the in-scope behavior | Baseline controls were moved into scope, blocked, or explicitly accepted as risk | Specialist approval for all production contexts is complete |
| Version boundary preserves compatibility without speculative surface | Current contract, immutable release behavior, future compatibility constraint, rejected placeholder list, and owner review | The current slice avoids v2 artifacts while not knowingly blocking planned evolution | The future design is fully decided |
| Prior source or task evidence boundary is current | Source paths, docs, tests, registry, route/schema/permission evidence, accepted/rejected memory, and freshness date | Reused prior boundary facts were checked against current evidence | repository inspection or memory is a complete source of truth |
| Validation is fresh after final scope edit | Command or review path, changed scope, exit code or manual result, artifact path, and final-edit timestamp | Not-present checks covered the final inspected state | Runtime feature flags, production config, or undocumented consumers are fully proven |
| Tool output is safe to retain | Action class, permission state, redaction rule, artifact path, retention owner, and rollback or cleanup path | Evidence collection avoids obvious secret/PII leakage and noisy full-output dumps | Every connector, export, or future debug artifact is safe |

## Current Evidence And Freshness

- Treat repository inspection, prior task evidence, previous plans, issue comments, generated artifacts, and prior validation as selectors until current source, docs, tests, registry, and owner evidence confirm them.
- Accept a prior "out of scope", "deferred", "v2", "no schema change", or "not present" claim only when current route, schema, UI, permission, job, flag, event, docs, and tests still match it.
- Mark scope evidence stale after edits to APIs, schemas, migrations, permissions, UI routes, jobs, events, feature flags, docs, tests, generated artifacts, release notes, or build outputs.
- For the current scope boundary, tie included behavior, excluded surfaces, forbidden placeholders, deferred decisions, compatibility constraints, validators, and handoff owners to fresh task-local evidence. Unavailable validation or owner confirmation remains named residual risk.

- If API/schema generation, migration dry run, feature flag edit, permission registry edit, or docs publication, record owner, compatibility check, rollback path, and not-present validation.
- If production config, live flag, admin console, support system, or connector write, require owner approval, stop condition, rollback or containment path, and redaction rule.
- For each not-present scan, record searched surfaces, whether forbidden artifacts were found, and residual unknowns.
