# Mission

Define the professional capability outcome this card guarantees when it is compiled into a ChangeForge skill reference.

# Capability Boundary

`capability-name` returns a narrow `template` decision fragment to selected professional skills. It does not replace the selected professional owner, expand the task, decide unrelated architecture or release scope, or close ordinary engineering work by itself.

# Load When
Use this capability when a product-change task requires the named engineering judgment, decision rule, risk screen, or output contract.

# Do Not Load When
Do not use this capability as a standalone tutorial, broad topic overview, language note, framework note, or runtime installation target outside the development profile.

# Used By / Owner Skill Compatibility
List professional skills that compile this capability into their references.

# Required Input Fragment

For `capability-name`, the owner skill must provide task intent, affected surface, current and desired behavior, relevant constraints, selected stage or mode, validation target, and material data/API/security/release boundaries. If that input is missing, return a missing-input fragment instead of guessing.

# Non-Negotiable Rules

- Preserve the capability boundary named by the registry entry.
- State decisions as professional engineering rules.
- Keep outputs concise enough to compile into skill references.
- Escalate when the capability cannot safely decide without additional domain authority.

# Industry Benchmarks

List recognized practices, review standards, model types, or engineering benchmarks that anchor this capability.

# Decision Rules
Describe the signals that select this capability over adjacent capabilities.

# Risk Escalation Rules

Define the risk thresholds that require handoff to another professional skill, a human reviewer, or a stricter verification gate.

# Critical Gotchas

# Reference Loading Policy

Use the body for ordinary routing and fragment decisions. Load references only when a selected owner skill needs deeper matrices, examples, benchmark detail, or validation mapping that will change the capability output. Do not create deep reference chains or load broad professional/domain references from this capability.

# Failure Modes

# Output Fragment
Define the required structure, evidence, and decision fields this capability contributes to a professional skill.

# Evidence Requirement

The capability output must name trigger evidence, inspected source or missing input, the decision returned to the owner, validation or evidence required, what remains unverified, and residual risk owner. Do not treat capability prose as proof.

# Quality Gate

State the checks that must pass before the capability output can be treated as complete.

# Return To Owner Skill

# Completion Criteria

The capability is complete when its rules, escalation thresholds, output contract, and handoff guidance are specific enough for professional skill compilation.
