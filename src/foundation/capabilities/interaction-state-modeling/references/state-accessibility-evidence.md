# State Accessibility Evidence

Use this evidence-pattern Reference only for the named state-accessibility-evidence decision.

## Evidence Contract

- Select urgency-appropriate `aria-busy`, `aria-live`, or `role="alert"` semantics while preserving programmatic relationships, keyboard operation, explainable unavailable actions, and focus.
- Bind an explainable disabled state to its prerequisite or permission signal, reachable affordance, description source, and keyboard evidence.
- Bind status evidence to live region, alert role, busy state, focus path, current screenshot, story, test, and final source.
- When evidence covers a bounded run, limit accessibility claims to the assistive technologies, routes, and design-system components exercised in that run.

Reject console-only or visual-only error feedback and disabled actions without an owned reason or recovery path.
