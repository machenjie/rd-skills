# State Accessibility Evidence

Use this evidence-pattern Reference only for the named state-accessibility-evidence decision.

## Evidence Contract

- Select urgency-appropriate status and announcement semantics for the actual platform, preserving programmatic relationships, keyboard operation, explainable unavailable actions, and focus. Web choices include `aria-busy`, `aria-live`, and `role="alert"`; native clients use their platform's accepted semantic and assistive mechanisms.
- Bind an explainable disabled state to its prerequisite or permission signal, reachable affordance, description source, and keyboard evidence.
- Bind status and focus evidence to the selected mechanism and final source.
- Use current tests, manual assistive results, screenshots, or stories that prove the affected behavior.
- Do not require an unselected alert or every artifact type.
- When evidence covers a bounded run, limit accessibility claims to the assistive technologies, routes, and design-system components exercised in that run.

Reject console-only or visual-only error feedback and disabled actions without an owned reason or recovery path.
