# State Evidence Freshness and Tool Boundary

Use this evidence-pattern Reference only for the named state-evidence-freshness-and-tool-boundary decision.

## Evidence Contract

- Treat repository inspection, prior task evidence, bug reports, generated context, stories, and old tests as selectors until current source, backend signals, stories, and fresh validation confirm them.
- Mark evidence stale after changes to API mapping, state ownership, disabled conditions, optimistic updates, timeouts, ARIA, stories, tests, reports, or generated artifacts.
- Bind each handoff claim to its current command, test, story, or owner review.
- Record missing evidence as not-run residual risk.
- For live experiments, production flags, configuration, or backend mutation, require environment, approval, stop, rollback, and redaction.
- Keep production telemetry, session replay, and support queries read-only or approved-connector scoped and redact private state.

Return freshness, tool authority, proof limits, and residual risk.
