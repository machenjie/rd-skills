# Consumer Impact Evidence Patterns

Use this reference when closure depends on repository inspection, prior task evidence, observable action sequence, telemetry freshness, generated artifact freshness, validation freshness, or evidence limits.

## Current Inventory And Freshness

- Record claim surface/class/risk, evidence source/result/freshness/limits/residual owner; inventory provider surfaces, clients/SDKs, events, CLI/packages/config/examples/jobs/dashboards/topics/telemetry, and external owners.
- Map generated/client/event/replay, deprecation/usage, and retained-state claims to compile/replay/contract/smoke/telemetry/owner evidence; refresh after contract/client/fixture/registry/export/example/telemetry-query/rollout changes.

## Proof Limits

- Search proves inspected paths, not dynamic/external/package/dashboard/copied/documentation consumers; structural diffs do not prove semantics/defaults/errors/timing/persistence/rollback.
- Provider tests do not prove consumers; generated compile does not prove mobile/partner adoption; telemetry proves only its dimensions/window.
- Prior evidence does not prove current contracts/consumers; disclose unavailable consumers, environments, instrumentation, and validation.

## Anti-Patterns

- A provider-only green test does not prove downstream compatibility.
- A public export, package, stream, webhook, or copied example can have consumers outside repository search scope.
- Calendar expiry without usage or owner evidence can remove a still-live contract.
- Generated output treated as incidental hides source-schema and compatibility drift.
