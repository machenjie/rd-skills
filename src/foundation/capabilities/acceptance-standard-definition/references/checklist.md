# Acceptance Standard Definition Checklist

- Replace vague terms with observable outcomes.
- Use condition, action, expected result, and evidence for each criterion.
- Include success, negative, permission, failure, edge, and regression standards when relevant.
- Define metric thresholds for performance, reliability, or quality claims.
- Define review owner for criteria requiring expert judgment.
- Mark release-blocking criteria.
- Map each standard to a requirement or scenario.
- Identify unacceptable outcomes.
- Avoid implementation details unless they are contractual constraints.
- Before accepting a standard, name a feasible verification artifact such as a test, report, query, review artifact, screenshot, or accountable stakeholder decision.
- Return criteria without feasible proof as unresolved acceptance decisions.
