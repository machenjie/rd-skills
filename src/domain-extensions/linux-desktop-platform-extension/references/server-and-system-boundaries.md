# Server and System Boundaries

Load this Reference only when Linux server, daemon, system service, or
host-runtime adjacency could misroute Professional or Domain ownership.

Official systemd and Linux man-pages pages below were accessed on 2026-07-24.

## Owner Decision

- Do not load `linux-desktop-platform-extension` for a Linux server, daemon,
  system service, kernel, container-host, or headless runtime change merely
  because the operating system is Linux.
- Select the actual Professional owner first: for example,
  `backend-change-builder` for bounded service implementation or
  `reliability-observability-gate` for recovery, SLO, or host-runtime behavior.
- Load `linux-systems-professional-usage` when process, signal, file, permission,
  namespace, cgroup, kernel, systemd, service, or Linux host semantics decide it.
- Add Linux Desktop only when a confirmed graphical-session surface also changes;
  keep service ownership and desktop integration acceptance separate.
- A systemd unit, D-Bus dependency, GTK/Qt library, or C/C++ language alone does
  not prove a Linux desktop target.

## Boundary Proof

- For a Linux server daemon, record the Professional and Linux systems
  Foundation, and prove Linux Desktop was rejected.
- For a graphical client plus companion daemon, record two owners, protocol,
  identity, lifecycle, install/update, failure isolation, and separate evidence.

## Required Record

Return selected Professional/Foundation/Domain composition, rejected
misrouting, target evidence, boundary behavior, validation split, and proof limits.
