# Professional Skill Router
Route once per task: path, start Profile, one primary Professional Skill, and Review Skill requirements only. The global Router carries no Layer 3 payload; the selected Professional Skill's generated selector is the sole Layer 3 selection payload. Skill routes expertise from Professional Risk Signals; Execution Level comes independently from residual reachable material risk. Main selects Layer 3 for Direct Task/Review and initial Analysis; an accepted Engineering Brief selects it for analyzed downstream Task/Review. When that owner must select, load only `engineering-control-plane/references/selectors/<professional-skill>.json`; exact Layer 3 skips selection signals only after itemwise Professional, profile, and Domain authorization. Runtime decision shards are located only by the selected Router row's source path, SHA-256, row pointer, trigger, start Profile, Primary Professional Skill, Review Skill, and selection owner; Layer 3 is shard output and must be post-validated, while scenario and fixture case identifiers are provenance only. More than three or duplicates fail closed, never truncate. Task/Review never reroute. A security signal does not by itself require `security-privacy-gate`, and selecting that Skill does not imply L4. Repository CLI, process, and path changes prefer `repository-tooling-change-builder` plus `filesystem-process-safety`; use `security-privacy-gate` only for a real trust, privilege, secret, or privacy boundary change. The global Review Boundary schedules one primary and zero or more specialist review-agent assignments. Each assignment has exactly one registered Review Skill and independently selects zero to three Layer 3 Skills from that Review Skill's candidates using review risk. Review-side selection never copies or unions the covered Tasks' implementation Layer 3. Analyzed implementation/repair starts with `engineering-change-analysis`; do not chain narrow analysis Skills over the same scope. Name `implementation-preparation`, `diagnosis-only`, or `source-backed-answer`; the latter two end at analysis without First Executable Slice, Task/Review Skill, or DAG. The table's Review Skill is a Task requirement for separately authorized later work, not Task-local assignment scheduling. Domain rows add Layer 3 modifiers only after Main fixes the base route. A Domain modifier requires its positive boundary and reciprocal Registry authorization, while anti-triggers keep neighboring ordinary work on its base route. Ordinary multi-task work uses combined final Diff review, not pre-implementation `high-risk-design-review`; use `engineering-artifact-review` only for an explicit Engineering Brief, Task Plan, contract, migration, architecture, or release artifact. Use `high-risk-design-review` only when its row is proved; `routing-quality-review` only for rd-skills routing authoring. Do not load the full Foundation or Domain catalog.
