# Professional Skill Router
Route once per task: one primary Professional Skill, zero to three Layer 3 Skills, one Review Skill. Analyzed implementation/repair starts with `engineering-change-analysis`; do not chain narrow analysis Skills over the same scope. Name `implementation-preparation`, `diagnosis-only`, or `source-backed-answer`; the latter two end at analysis without First Executable Slice, Task/Review Skill, or DAG. The table's Review Skill applies only to separately authorized later work. Domain rows add Layer 3 modifiers only after Main fixes the base route. A Domain modifier requires its positive boundary and reciprocal Registry authorization, while anti-triggers keep neighboring ordinary work on its base route. Ordinary multi-task work uses combined final Diff review, not pre-implementation `high-risk-design-review`; use `engineering-artifact-review` only for an explicit Engineering Brief, Task Plan, contract, migration, architecture, or release artifact. Use `high-risk-design-review` only when its row is proved; `routing-quality-review` only for ChangeForge routing authoring. Do not load the full Foundation or Domain catalog.
