# Logging Output And Gates

Use this targeted Reference only for mode-specific logging closure and gates when selected purpose, placement, schema safety, correlation, volume, sink, or failure visibility requires more than the root.

## Do Not Load

Do not load when no logging behavior changes, the root or compact checklist closes the decision, or selection criteria alone resolves the concrete choice.

## Mode Closure

- **Task:** return the actual logging diff, post-edit validation, preserved behavior, proof limits, residual risk, and independent-review owner.
- Leave approval to the independent-review owner.
- **Review:** return `Approved`, `Returned`, or `Blocked`, reviewed/unreviewed files, findings, evidence limits, and no repair. For `Blocked`, name missing evidence, unblock condition, repair owner, and handoff.

## Triggered Gates

- **Purpose:** name the diagnostic, audit, security, or operational question and choose a log only when a better current metric, trace, test, alert, or no-new-signal outcome does not answer it.
- **Placement and level:** name the boundary owning the final outcome, current policy, operator action, and reachable validated failure states. For audit evidence, name its consumer and protected meaning.
- **Fields:** include only purpose-required stable fields and their sources.
- Require policy-consistent omission or tested transformation for classified data.
- **Correlation:** preserve the boundary-supported linkage needed for the question without requiring unrelated identifiers or exposing raw identity.
- **Volume and cardinality:** when rate or value space is material, record assumptions and cost/noise impact, then choose measured sampling, aggregation, rate control, lower level, metric conversion, shorter retention, or no log.
- **Retention, access, and sinks:** when classification or platform policy changes these boundaries, name the selected separation and owner; do not invent universal sinks or periods.
- **Failure visibility:** distinguish decision-relevant validation, retry, fallback, degradation, and terminal states without claiming unobserved states.

## Evidence And Limits

Tie each gate to final-edit tests, captured events, schema/redaction checks, logger configuration, sink evidence, or measurements. Local evidence does not prove production traffic, sink configuration, retention, downstream transformation, or unusual framework paths; name each unverified boundary and residual leakage or diagnosability risk.
