# Technical Investigation

- Frame the unresolved question, constraints, candidates, and decision deadline.
- Accept a question without a repository when external technical facts determine the answer.
- Prefer target-version official documentation, specifications, release notes, and source.
- Bind each material claim to its source, version, retrieval context, and applicable environment.
- Separate observed facts, supported inference, and unverified assumptions.
- Compare candidates against the same behavior, operational constraints, and failure conditions.
- Identify what documentation cannot establish and define the smallest discriminating experiment.
- Keep investigation read-only. Delegate code-writing, installation, or environment mutation to an authorized implementation owner.
- Return the conclusion, rejected alternatives, validity boundary, and remaining experiment needs.

## Evidence Limits

- A feature name does not establish version compatibility or operational semantics.
- A runnable demo does not establish production capacity, recovery, or maintainability.
- Existing implementation choices need no investigation when current evidence already resolves them.
